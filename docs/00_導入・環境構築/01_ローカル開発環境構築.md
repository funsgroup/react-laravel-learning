# 01_ローカル開発環境構築

## 1. この資料の目的

この資料は、React SPA と Laravel API で構成された業務管理システムサンプルを、Windows 11 上で開発・実行するための環境構築手順です。

対象は、Windows 11、VS Code、WSL2 Ubuntu、Docker Desktop を使って、React 画面、Laravel API、MySQL をまとめて動かす構成です。初めて環境を作る人でも迷いにくいように、「どこで実行するか」と「何が確認できればOKか」を手順ごとに書いています。

### 学習開始前にやる範囲

Laravel の学習を始める前に、この資料の **第1章〜第5章** までを完了します。ここでのゴールは、アプリを起動することではなく、`backend/` を作り始められる状態にすることです。

最初に必要な作業は次の範囲です。

| やること | 完了の目安 |
|---|---|
| Windows Terminal、VS Code、Docker Desktop を入れる | Windows 側で開発用アプリを起動できる |
| WSL2 Ubuntu を使えるようにする | `wsl -l -v` で Ubuntu の `VERSION` が `2` になっている |
| Docker Desktop の WSL Integration を有効にする | Ubuntu 側で `docker version` と `docker compose version` が表示される |
| Ubuntu 側で Git と SSH を確認する | `git --version` と `ssh -T git@github.com` を確認できる |
| GitHub からリポジトリを clone する | `/home/<user>/dev/react-laravel-learning` にプロジェクトがある |
| VS Code を WSL で開く | VS Code 左下に `WSL: Ubuntu` と表示される |

ここまでできたら、[Laravel 学習ステップ](../05_Laravel学習ステップ/01_学習ロードマップ.md) に進み、`backend/` を作成します。

この資料の **第6章以降** にある `docker compose up --build`、ログイン確認、Laravel テストは、`backend/` を作成した後に使う確認手順です。`backend/` がまだない段階では実行しません。

### 重要: backend 作成前の注意

このリポジトリは `backend/` を自分で作る学習状態です。Laravel API の `backend/` をまだ作成していない場合、`docker compose up --build` や Laravel のテストは実行できません。

第1章〜第5章の準備が終わったら、[Laravel 学習ステップ](../05_Laravel学習ステップ/01_学習ロードマップ.md) に沿って `backend/` を作成してください。この資料の起動手順や Laravel テスト手順は、`backend/` 作成後に使う確認手順です。

### 完成品版と見比べるときの注意

`react-laravel-learning` は `backend/` を自分で作る学習版、`react-laravel-complete` は完成品版です。
両方を同じ PC で同時に起動しやすいように、完成品版は学習版とは手元の PC から見えるポートとコンテナ名を分けています。これは環境上の差分であり、画面仕様や API 仕様の学習差分ではありません。

| リポジトリ | React | Laravel API | MySQL |
|---|---|---|---|
| `react-laravel-learning` | `http://localhost:5173` | `http://localhost:8000` | `localhost:3306` |
| `react-laravel-complete` | `http://localhost:5174` | `http://localhost:8001` | `localhost:3307` |

### 学習者向けメモ

この資料では、コマンドを実行する場所が重要です。`wsl` は Windows 側の PowerShell、`git` や `docker compose` は Ubuntu 側で実行します。迷った場合は、ターミナルの表示が `/home/...` になっているか、`PS C:\...` になっているかを確認してください。

エラーが出たときは、まず「どの手順の、どのコマンドで失敗したか」を記録します。環境構築の失敗は、Docker Desktop の起動状態、WSL Integration の設定、ポート番号の重複、GitHub の SSH 鍵設定の違いで起きることが多いです。

## 2. システム概要

このシステムは、顧客、案件、タスクを管理する学習用の業務管理サンプルです。

```text
利用者がログインする
  ↓
顧客を登録・確認する
  ↓
顧客に紐づく案件を登録・確認する
  ↓
案件に紐づくタスクを登録・確認する
  ↓
ダッシュボードで件数や期限間近のタスクを確認する
```

バックエンドは学習ステップで作成する Laravel API、フロントエンドは React + Vite + TypeScript、データベースは MySQL で構成されています。Docker Compose を使うと、`backend/` 作成後に必要なコンテナをまとめて起動できます。

`docker-compose.yml` の MySQL は、学習時の環境差を減らすために `mysql:9.7.0` に固定しています。別環境で作成した MySQL 8.4 系などの既存データボリュームを使う場合は、起動前に必要なデータをバックアップしてください。

## 3. 利用ツール

| ツール | 主な用途 | 入れる場所 |
|---|---|---|
| Windows Terminal | PowerShell や Ubuntu を開く | Windows 11 |
| VS Code | WSL 内のコード編集、ターミナル操作 | Windows 11 |
| WSL2 Ubuntu | Git、Docker CLI、Linux コマンド操作 | Windows 11 上の Linux 環境 |
| Docker Desktop | MySQL、Laravel、React のコンテナ実行 | Windows 11 |
| MySQL | アプリ DB | Docker コンテナ |
| Postman | API の手動確認。任意 | Windows 11 |
| GitHub | ソースコードとドキュメントの管理 | Web サービス |

PHP、Composer、Node.js、npm は Docker コンテナ内で使うため、通常は Ubuntu 側へ直接インストールしなくても起動できます。Ubuntu 側では、Git と Docker CLI が使える状態を目指します。

## 4. Windows 11 側の準備

この章は Windows 11 側で行います。PowerShell のコマンドは、Windows Terminal で PowerShell を開いて実行します。

### 4.1 Windows 側アプリをインストールする

Windows 側へ次のツールをインストールします。

| ツール | 用途 |
|---|---|
| Windows Terminal | PowerShell / Ubuntu を開く |
| VS Code | 開発用エディタ |
| Docker Desktop | Docker 実行基盤 |
| Postman | 任意。API を手動確認したい場合に使う |
| Git for Windows | 任意。Windows 側でも Git 操作をしたい場合だけ使う |

開発作業は基本的に WSL2 Ubuntu 側で行います。Windows 側の `C:\Users\...` 配下ではなく、Ubuntu 側の `/home/<user>/...` 配下にリポジトリを置くと、Docker や Linux コマンドとの相性がよくなります。

### 4.2 WSL2 Ubuntu をインストールする

管理者 PowerShell で実行します。

```powershell
wsl --install
```

再起動を求められた場合は、Windows を再起動します。再起動後、Ubuntu を起動し、Linux ユーザー名とパスワードを作成します。

PowerShell で確認します。

```powershell
wsl -l -v
```

期待値:

```text
NAME      STATE           VERSION
Ubuntu    Running         2
```

`VERSION` が `2` になっていれば、WSL2 Ubuntu として動いています。

### 4.3 Docker Desktop を設定する

Docker Desktop を起動し、Windows 側の Docker Desktop 設定画面で次を有効にします。

```text
Settings
  -> General
    -> Use the WSL 2 based engine: ON

Settings
  -> Resources
    -> WSL Integration
      -> Ubuntu: ON
```

このプロジェクトでは、Docker Desktop の WSL Integration を使って Ubuntu 側から Docker を操作します。Ubuntu に Docker Engine を直接インストールする必要はありません。

### 4.4 VS Code 拡張機能を入れる

Windows 側の VS Code で、次の拡張機能を入れます。

```text
WSL
Docker
PHP Intelephense
Laravel Extension Pack
ESLint
YAML
GitLens 任意
```

`WSL` 拡張機能を入れておくと、Ubuntu 側のリポジトリを VS Code から直接開けます。

## 5. WSL2 Ubuntu 側の設定

ここからは Ubuntu 側で実行します。Windows Terminal で Ubuntu を開いても、VS Code の Ubuntu ターミナルを使っても構いません。

**Ubuntu の開き方**

Windows Terminal から開く場合は、スタートメニューで `Windows Terminal` を検索して起動します。上部のタブ横にある `∨` をクリックし、一覧から `Ubuntu` を選びます。

VS Code から開く場合は、VS Code 左下に `WSL: Ubuntu` と表示されている状態で、上部メニューから `Terminal` -> `New Terminal` を選びます。日本語表示の場合は、`ターミナル` -> `新しいターミナル` を選びます。

Ubuntu 側で開けている場合、ターミナルには `ユーザー名@PC名:~$` のような表示が出ます。`pwd` を実行して `/home/<user>` から始まる場所が表示されれば Ubuntu 側です。`PS C:\...` と表示されている場合は Windows 側の PowerShell なので、Ubuntu のコマンドを実行する前に Ubuntu を開き直してください。

### 5.1 Git と SSH クライアントを確認する

Ubuntu 側で Git と SSH クライアントを確認します。

```bash
git --version
ssh -V
```

`git: command not found` や `ssh: command not found` のようなエラーになる場合は、Ubuntu 側で次を実行してください。

```bash
sudo apt update
sudo apt install -y git openssh-client
```

### 5.2 GitHub 用の SSH 鍵を確認する

GitHub へ SSH 接続するために、Ubuntu 側で SSH 鍵を確認します。

```bash
ls ~/.ssh/id_ed25519.pub
```

`No such file or directory` と表示された場合は、まだ SSH 鍵がありません。次のコマンドで SSH 鍵を作成します。メールアドレスは、GitHub に登録しているメールアドレスへ置き換えてください。

```bash
ssh-keygen -t ed25519 -C "GitHubのメールアドレス"
```

保存先を聞かれたら、特別な理由がなければ Enter を押して初期値のまま進めます。パスフレーズは任意です。設定すると、鍵を使うときに追加のパスワード入力が必要になります。

公開鍵を表示します。

```bash
cat ~/.ssh/id_ed25519.pub
```

表示された `ssh-ed25519` で始まる 1 行をコピーし、GitHub の画面で次の場所に登録します。

```text
Settings
  -> SSH and GPG keys
    -> New SSH key
```

登録できたら、Ubuntu 側で GitHub への SSH 接続を確認します。

```bash
ssh -T git@github.com
```

初回接続時に `Are you sure you want to continue connecting` と表示された場合は、`yes` と入力します。`You've successfully authenticated` と表示されれば、SSH 接続は成功です。

`Permission denied (publickey)` と表示される場合は、SSH 鍵が GitHub に登録されていない、別の鍵を見ている、またはリポジトリへの権限がない可能性があります。公開鍵の登録内容と GitHub アカウントの権限を確認してください。

### 5.3 リポジトリをダウンロードする

SSH 接続が確認できたら、Ubuntu 側にプロジェクト用のディレクトリを作り、GitHub からリポジトリをダウンロードします。

```bash
mkdir -p ~/dev
cd ~/dev
git clone git@github.com:funsgroup/react-laravel-learning.git react-laravel-learning
cd react-laravel-learning
```

配置場所は次の形になります。

```text
/home/<user>/dev/react-laravel-learning
```

この資料の以降のコマンドは、特別な指定がない限り `~/dev/react-laravel-learning` で実行します。

### 5.4 Docker CLI を確認する

Docker Desktop を起動した状態で、Ubuntu 側で確認します。

```bash
docker version
docker compose version
```

Docker クライアントと Docker Compose のバージョンが表示されれば OK です。

`Cannot connect to the Docker daemon` や `permission denied while trying to connect to the Docker daemon` が出る場合は、Ubuntu 側の Docker CLI から Docker Desktop へ接続できていません。Docker Desktop を起動し、WSL Integration の `Ubuntu` が ON になっているか確認してから、Ubuntu のターミナルを開き直してください。

### 5.5 VS Code でプロジェクトを開く

Ubuntu 側で次を実行します。

```bash
cd ~/dev/react-laravel-learning
code .
```

VS Code 左下に `WSL: Ubuntu` と表示されていれば OK です。表示されていない場合は、Windows 側のフォルダとして開いている可能性があります。

確認するポイント:

```text
VS Code 左下に WSL: Ubuntu と表示されている
VS Code で開いているフォルダが /home/<user>/dev/react-laravel-learning になっている
```

`backend` や `frontend` だけを開くのではなく、リポジトリルートである `react-laravel-learning` を開くと、Docker Compose やドキュメントの場所を見失いにくくなります。

### 5.6 ここまでできたら学習を始める

第5章まで完了していれば、Laravel 学習を始める準備はできています。この時点では、まだ `backend/` がないため、アプリ全体の起動や Laravel テストはできなくて問題ありません。

次は [Laravel 学習ステップ](../05_Laravel学習ステップ/01_学習ロードマップ.md) に進み、`backend/` に Laravel プロジェクトを作成します。

## 6. React、Laravel、MySQL を起動する

この章は、`backend/` を作成した後に実行します。まだ `backend/` がない場合は、先に [Laravel 学習ステップ](../05_Laravel学習ステップ/01_学習ロードマップ.md) を進めてください。

Ubuntu 側のターミナルで実行します。VS Code のターミナルでも構いません。

```bash
cd ~/dev/react-laravel-learning
docker compose up --build
```

このコマンドで、次のコンテナが起動します。

| コンテナ | 役割 | 主なポート |
|---|---|---|
| `business_sample_mysql` | MySQL DB | `3306` |
| `business_sample_backend` | Laravel API | `8000` |
| `business_sample_frontend` | React + Vite | `5173` |

`--build` は、Laravel 用の PHP コンテナを Dockerfile から作り直す指定です。初回起動や Dockerfile 変更後は `--build` を付けます。普段の再起動だけなら `docker compose up` でも動きます。

起動中のターミナルにはログが流れ続けます。停止したい場合は、同じターミナルで `Ctrl+C` を押します。

別のターミナルで起動状態を確認したい場合は、Ubuntu 側で次を実行します。

```bash
cd ~/dev/react-laravel-learning
docker compose ps
```

`mysql`、`backend`、`frontend` が表示され、停止していなければ OK です。

## 7. 起動を確認する

ブラウザで React 画面を開きます。

```text
http://localhost:5173
```

ログイン画面または業務管理画面が表示されれば、React の起動確認は OK です。

Laravel API は次の URL で確認できます。

```text
http://localhost:8000
```

Laravel のレスポンスが表示されれば、API サーバーが起動しています。API の多くはログイン後に使うため、未ログイン状態で直接 API URL を開くと `401 Unauthorized` や JSON レスポンスが表示されることがあります。これは認証が必要な API では正常な動きです。

### 7.1 初期ユーザーでログインする

初期データとして、次のユーザーが作成されます。

| 権限 | メールアドレス | パスワード |
|---|---|---|
| 管理者 | `admin@example.com` | `password` |
| 担当者 | `staff@example.com` | `password` |

管理者は削除操作ができます。担当者は登録・編集が中心で、削除ボタンは表示されません。

ログイン後、次の操作ができれば、React、Laravel、MySQL の接続を含めて起動確認ができています。

```text
ダッシュボードが表示される
顧客一覧が表示される
案件一覧が表示される
タスク一覧が表示される
```

## 8. よく使うコマンド

この章のコマンドは、Ubuntu 側の `~/dev/react-laravel-learning` で実行します。Laravel 関連のコマンドと全体起動は、`backend/` 作成後に実行してください。

### 8.1 停止する

起動中のターミナルで `Ctrl+C` を押すと、前面で動いているコンテナを停止できます。

コンテナを削除したい場合は、次を実行します。

```bash
docker compose down
```

### 8.2 データベースを含めて初期化する

MySQL の保存データも削除して、最初から作り直したい場合は `-v` を付けます。この操作後の起動は、`backend/` 作成済みの状態で実行します。

```bash
docker compose down -v
docker compose up --build
```

`-v` を付けると登録済みの顧客、案件、タスクも消えます。学習用データを最初から作り直したい場合だけ使ってください。

### 8.3 Docker 一式をクリーンアップする

このプロジェクトの Docker Compose で作成したものをまとめて削除したい場合は、次を実行します。

```bash
docker compose down -v --rmi local --remove-orphans
```

このコマンドで削除される主なものは次のとおりです。

| 削除されるもの | 内容 |
|---|---|
| コンテナ | `business_sample_mysql`、`business_sample_backend`、`business_sample_frontend` など |
| ネットワーク | Docker Compose がこのプロジェクト用に作成したネットワーク |
| MySQL volume | Compose で定義した `mysql-data`。顧客、案件、タスク、ユーザーなどの DB データ |
| ローカルイメージ | Docker Compose がビルドした Laravel 用のローカルイメージ |
| 孤立コンテナ | compose 設定から外れた古いコンテナ |

`-v` は MySQL の保存データを削除する指定です。実行すると登録済みの顧客、案件、タスク、ログインユーザーなどは消えます。必要なデータがある場合は、実行前にバックアップやメモを残してください。

クリーンアップ後にもう一度起動する場合は、`backend/` 作成後に次を実行します。

```bash
docker compose up --build
```

### 8.4 Laravel のテーブルを作り直す

Docker volume は残したまま、Laravel のテーブルだけを作り直して初期データを入れ直したい場合は、次を実行します。

```bash
docker compose run --rm backend php artisan migrate:fresh --seed
```

このコマンドでも、登録済みの顧客、案件、タスクなどのアプリデータは消えます。Docker のコンテナやイメージまで消したい場合は、前の「Docker 一式をクリーンアップする」を使ってください。

### 8.5 Laravel のテストを実行する

このコマンドは、Laravel 学習ステップで `backend/` とテストを作成した後に実行します。

```bash
docker compose run --rm backend php artisan test
```

テストでは MySQL 内の `business_sample_test` を使うため、普段の開発用 DB `business_sample` は変更されません。

### 8.6 React のビルドを確認する

```bash
docker compose run --rm --no-deps frontend npm run build
```

TypeScript の型エラーやビルドエラーがあると失敗します。

### 8.7 React の Lint を確認する

```bash
docker compose run --rm --no-deps frontend npm run lint
```

コードの書き方や React Hooks の使い方に問題がないかを確認します。

### 8.8 Docker Compose の設定を確認する

```bash
docker compose config
```

`docker-compose.yml` が正しい YAML として読めるか確認できます。コンテナを起動する前に設定だけ見たいときに便利です。

## 9. よくあるトラブルと確認ポイント

### 9.1 Docker が起動していない

症状:

```text
Cannot connect to the Docker daemon
```

確認すること:

```text
Docker Desktop が起動している
Docker Desktop の WSL Integration で Ubuntu が ON になっている
Ubuntu のターミナルを開き直している
```

設定を変えた直後は、Ubuntu のターミナルを一度閉じて開き直すと反映されることがあります。

### 9.2 ポートがすでに使われている

このプロジェクトでは、主に次のポートを使います。

| ポート | 用途 |
|---|---|
| `3306` | MySQL |
| `8000` | Laravel API |
| `5173` | React 画面 |

症状:

```text
Bind for 0.0.0.0:5173 failed: port is already allocated
```

確認すること:

```text
同じポートを使う別プロジェクトやコンテナが動いていないか
以前起動したコンテナが残っていないか
```

まず、起動中のコンテナを確認します。

```bash
docker ps
```

このプロジェクトのコンテナを停止する場合は、リポジトリルートで次を実行します。

```bash
docker compose down
```

### 9.3 初期データが期待どおりに戻らない

MySQL のデータは Docker volume に保存されます。そのため、コンテナを作り直しても登録済みデータが残ることがあります。

完全に初期化したい場合は、次を実行します。`docker compose up --build` は `backend/` 作成後に実行してください。

```bash
docker compose down -v
docker compose up --build
```

`-v` は DB データを削除する強い操作です。必要なデータがある場合は、実行前にバックアップやメモを残してください。

### 9.4 テスト DB が存在しない

通常は初回起動時に `docker/mysql/init/01-create-test-database.sql` からテスト用 DB が作成されます。すでに MySQL volume を作成済みの場合、初期化 SQL は自動再実行されません。

テスト実行時に `business_sample_test` が存在しないエラーが出る場合は、次を一度だけ実行します。

```bash
docker compose exec mysql mysql -uroot -proot_secret -e "CREATE DATABASE IF NOT EXISTS business_sample_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; GRANT ALL PRIVILEGES ON business_sample_test.* TO 'app_user'@'%';"
```

その後、`backend/` 作成後にもう一度テストを実行します。

```bash
docker compose run --rm backend php artisan test
```

### 9.5 GitHub から clone できない

症状:

```text
Permission denied (publickey)
```

確認すること:

```text
Ubuntu 側で作成した公開鍵を GitHub に登録している
ssh -T git@github.com が成功している
GitHub アカウントに funsgroup/react-laravel-learning リポジトリの権限がある
```

Windows 側で作った SSH 鍵と Ubuntu 側で使う SSH 鍵は別物として扱われることがあります。この資料の手順では、Ubuntu 側の `~/.ssh/id_ed25519.pub` を GitHub に登録します。
