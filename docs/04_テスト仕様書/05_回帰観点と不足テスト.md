# 業務管理システム テスト仕様書 05_回帰観点と不足テスト

## 1. 回帰テスト観点

次の変更を行った場合は、関連する回帰テストを重点的に実施します。

| 変更内容 | 重点確認 |
| --- | --- |
| 認証・Cookie設定変更 | ログイン、ログアウト、画面初期表示、CSRFエラーの有無 |
| Controllerのバリデーション変更 | 登録、更新、入力エラー、画面のエラー表示 |
| DBリレーション変更 | 顧客削除時の案件、案件削除時のタスク、担当者null化 |
| TypeScript型変更 | 画面ビルド、一覧表示、フォーム保存 |
| 権限仕様変更 | 削除ボタン表示、APIの `403 Forbidden` |

## 2. 現時点の不足テスト

現行リポジトリで不足している主なテストは次のとおりです。

- React画面の自動テストがない。
- ブラウザ上のログインからCRUDまでを通すE2Eテストがない。
- 顧客、案件、タスクの全バリデーションパターンを網羅するテストがない。
- 顧客削除時に案件、タスクまで削除されることを明示的に確認するテストがない。
- APIの検索・絞り込みクエリを確認するテストがない。
- `staff` が案件・タスクを削除できないことを個別に確認するテストがない。

これらはシステムの品質を上げるため、今後追加することが望ましいです。
