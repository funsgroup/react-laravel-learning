# 業務管理システム テスト仕様書 01_テスト概要

## 1. 文書の目的

本書は、業務管理システムサンプルで確認すべきテスト観点、テストケース、既存テストとの対応をまとめた文書です。

このリポジトリは `backend/` を自分で作る学習状態です。そのため、Laravel API の自動テストは [Laravel 学習ステップ](../05_Laravel学習ステップ/01_学習ロードマップ.md) に沿って `backend/` を作成した後に実装・実行します。

Laravel API の自動テストは、作成後の `backend/tests/Feature/` に配置します。ブラウザ操作を含むE2Eテストは現行リポジトリには未実装のため、本書では手動確認または将来のE2E自動化候補として記載します。

## 2. テスト対象

| 対象 | 内容 |
| --- | --- |
| 認証 | ログイン、ログアウト、ログイン状態復元、未ログイン制御 |
| 権限 | `admin` と `staff` の削除可否 |
| 顧客管理 | 一覧、登録、編集、削除、入力チェック |
| 案件管理 | 一覧、登録、編集、削除、入力チェック、担当者自動設定 |
| タスク管理 | 一覧、登録、編集、削除、入力チェック、担当者自動設定 |
| ダッシュボード | 件数、案件ステータス別件数、期限間近タスク |
| 画面 | タブ切り替え、フォーム表示、エラー表示、再読み込み |

## 3. 実行コマンド

Laravel の Feature Test は、`backend/` 作成後に次のコマンドで実行します。

```bash
docker compose run --rm -e APP_ENV=testing -e DB_CONNECTION=sqlite -e DB_DATABASE=:memory: -e SESSION_DRIVER=array backend php artisan test
```

React/TypeScript のビルド確認は次のコマンドで実行します。

```bash
docker compose run --rm --no-deps frontend npm run build
```

Docker Compose の設定確認は次のコマンドで実行します。

```bash
docker compose config
```
