# 業務管理システム 要件定義書 04_非機能要件と制約

## 1. 入力要件

| 対象 | 必須項目 | 主な制約 |
| --- | --- | --- |
| ログイン | メールアドレス、パスワード | メールアドレス形式であること |
| 顧客 | 会社名、状態 | 会社名は255文字以内、メールはメール形式、状態は定義済み値 |
| 案件 | 顧客、件名、金額、状態 | 金額は0以上、期限は開始日以降、状態は定義済み値 |
| タスク | 案件、件名、状態 | 案件は存在すること、状態は定義済み値 |

## 2. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 実行環境 | Docker Compose で React、Laravel、MySQL をまとめて起動できる。 |
| 開発容易性 | 初期データ投入により、起動直後から画面操作を確認できる。 |
| セキュリティ | Laravel Sanctum の Cookie 認証を使用し、ログインAPIはCSRF Cookie取得後に呼び出す。 |
| セキュリティ | ログイン成功時にセッションIDを再生成し、セッション固定攻撃を防ぐ。 |
| 認可 | 削除操作は API 側でも `admin` に制限する。 |
| 保守性 | API のレスポンス形式は基本的に `{ data: ... }` にそろえる。 |
| テスト | Laravel Feature Test により認証、業務データ作成、権限、ダッシュボードを検証する。 |

## 3. 制約

- 本システムは学習用サンプルであり、本番運用向けの監査ログ、詳細な権限管理、ユーザー管理画面は未実装です。
- フロントエンドは1つの React コンポーネント `App.tsx` に主要画面をまとめています。
- バックエンドには検索・絞り込み用のクエリパラメータがありますが、現行画面では検索フォームや絞り込みUIは実装されていません。
- 一覧APIはページネーションせず、対象データをまとめて返します。
- ファイルアップロード、メール送信、通知、外部サービス連携は対象外です。

## 4. 今後の課題

- 一覧の検索、絞り込み、ページネーションUIを追加する。
- ユーザー管理画面を追加し、管理者が利用者を作成・編集できるようにする。
- 削除操作を物理削除ではなく論理削除にするか検討する。
- 監査ログを追加し、誰がいつ登録・編集・削除したか追跡できるようにする。
- Playwright などでブラウザ操作を含む E2E テストを追加する。
- 本番利用する場合は、環境変数、Cookie設定、HTTPS、バックアップ、ログ監視を整備する。
