# Laravel 学習ステップ 01_学習ロードマップ

**このリポジトリは backend を自分で作る学習状態です。**

この資料は、空の `backend/` から Laravel API を作り、React 画面と連携できるところまで進めるための段階別カリキュラムです。完成コードを最初から読むのではなく、Laravel のプロジェクト作成、設定、Model、Migration、Controller、テストを順番に手を動かして学びます。

## 1. ゴール

最終的に、React から次の Laravel API を呼べる状態を目指します。

| 分類 | API |
| --- | --- |
| 認証 | `POST /api/login`、`POST /api/logout`、`GET /api/me` |
| ダッシュボード | `GET /api/dashboard/summary` |
| 顧客 | `GET /api/customers`、`POST /api/customers`、`GET /api/customers/{customer}`、`PUT /api/customers/{customer}`、`DELETE /api/customers/{customer}` |
| 案件 | `GET /api/projects`、`POST /api/projects`、`GET /api/projects/{project}`、`PUT /api/projects/{project}`、`DELETE /api/projects/{project}` |
| タスク | `GET /api/tasks`、`POST /api/tasks`、`GET /api/tasks/{task}`、`PUT /api/tasks/{task}`、`DELETE /api/tasks/{task}` |

詳しい API 仕様は [詳細設計書: API詳細](../03_詳細設計書/02_API詳細.md) を参照します。この学習資料では「何を、どの順番で作るか」を中心に説明します。

## 2. 始める前の確認

この資料を始める前に、[ローカル開発環境構築](../00_導入・環境構築/01_ローカル開発環境構築.md) の第1章〜第5章までを完了しておきます。Windows、WSL2 Ubuntu、Docker Desktop、GitHub からの clone、VS Code の WSL 接続までできていれば、このロードマップを始められます。

第6章以降の `docker compose up --build`、ログイン確認、Laravel テストは、`backend/` を作成した後に行う確認手順です。

コマンドは、特別な指定がない限りリポジトリルートで実行します。

```bash
cd ~/dev/react-laravel-learning
```

`backend/` は学習で作成するため、最初は存在しない状態です。もし以前の作業で空の `backend/` が残っている場合は、中に必要なファイルがないことを確認してから進めます。

Docker Compose の設定だけ先に確認できます。

```bash
docker compose config
```

この時点では `docker compose up --build` は実行しません。Laravel のファイルがまだないため、backend コンテナが起動できないからです。

## 4. Step 1: Laravel プロジェクトを作成する

### 目的

Laravel の標準プロジェクトを `backend/` に作成します。ここで作られる `artisan`、`app/`、`routes/`、`database/` が、以降の学習の土台になります。

### 作業

まず、空の `backend/` を作成します。

```bash
mkdir backend
```

Laravel 用の PHP イメージをビルドします。

```bash
docker compose build backend
```

`backend/` の中に Laravel を作成します。

```bash
docker compose run --rm --no-deps backend composer create-project laravel/laravel . "^13.0"
```

作成できたか確認します。

```bash
ls backend
```

`artisan`、`composer.json`、`app`、`routes`、`database` が見えれば OK です。

### 学習者向けメモ

`composer create-project` は、Laravel の雛形と依存パッケージをまとめて作るコマンドです。ここでは Docker の `backend` サービス内で Composer を実行しているため、手元の PC に PHP や Composer を直接インストールしなくても進められます。

## 5. Step 2: MySQL、Session、CORS、Sanctum を設定する

### 目的

React 画面から Laravel API を呼ぶために、DB 接続、セッション、CORS、Sanctum Cookie 認証を設定します。

### 作業

Sanctum を追加します。

```bash
docker compose run --rm --no-deps backend composer require laravel/sanctum
```

API と Sanctum の基本設定を追加します。

```bash
docker compose run --rm --no-deps backend php artisan install:api
```

`backend/.env` を開き、Docker Compose の MySQL と合うように設定します。

```dotenv
APP_URL=http://localhost:8000

DB_CONNECTION=mysql
DB_HOST=mysql
DB_PORT=3306
DB_DATABASE=business_sample
DB_USERNAME=app_user
DB_PASSWORD=secret

SESSION_DRIVER=database
SANCTUM_STATEFUL_DOMAINS=localhost:5173,127.0.0.1:5173,localhost:8000,127.0.0.1:8000
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

`backend/bootstrap/app.php` では、API ルートと Sanctum の Cookie 認証を有効にします。

```php
<?php

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Illuminate\Http\Request;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware): void {
        // React から送られる Cookie を、Sanctum の認証に使えるようにします。
        $middleware->statefulApi();
    })
    ->withExceptions(function (Exceptions $exceptions): void {
        // API では HTML ではなく JSON のエラーを返すようにします。
        $exceptions->shouldRenderJsonWhen(
            fn (Request $request) => $request->is('api/*'),
        );
    })->create();
```

Laravel の設定キャッシュを消し、最新の `.env` を読み直します。

```bash
docker compose run --rm --no-deps backend php artisan config:clear
```

### 完了条件

- `backend/routes/api.php` が存在する。
- `backend/bootstrap/app.php` で `api` ルートと `$middleware->statefulApi()` を設定している。
- `backend/.env` が Docker Compose の MySQL 設定と合っている。

## 6. Step 3: 認証 API を作る

### 目的

React 画面からログイン、ログアウト、ログイン状態確認ができるようにします。

### 作業

Controller を作成します。

```bash
docker compose run --rm --no-deps backend php artisan make:controller Api/AuthController
```

`AuthController` には、次の 3 つのメソッドを作ります。

| メソッド | 役割 |
| --- | --- |
| `login()` | メールアドレスとパスワードでログインする |
| `logout()` | セッションを破棄してログアウトする |
| `me()` | ログイン中のユーザー情報を返す |

実装では、学習者が処理の意味を追えるように日本語コメントを入れます。

```php
/**
 * メールアドレスとパスワードでログインします。
 *
 * React 側は先に /sanctum/csrf-cookie を呼び、CSRF Cookie を受け取ってから
 * この API を呼び出します。ログインに成功するとセッション Cookie が有効になります。
 */
public function login(Request $request): JsonResponse
{
    // まず入力値の形を確認します。失敗すると Laravel が 422 レスポンスを返します。
    $credentials = $request->validate([
        'email' => ['required', 'email'],
        'password' => ['required', 'string'],
    ]);

    // ここで users テーブルの email/password を照合します。
    if (! Auth::attempt($credentials, $request->boolean('remember'))) {
        throw ValidationException::withMessages([
            'email' => ['メールアドレスまたはパスワードが正しくありません。'],
        ]);
    }

    // ログイン直後にセッション ID を作り直し、安全性を高めます。
    $request->session()->regenerate();

    return response()->json([
        'user' => $request->user(),
    ]);
}
```

`backend/routes/api.php` にルートを追加します。

```php
use App\Http\Controllers\Api\AuthController;
use Illuminate\Support\Facades\Route;

// ログイン前に呼べる API です。
Route::post('/login', [AuthController::class, 'login']);

// auth:sanctum の中は、ログイン済みユーザーだけが呼べます。
Route::middleware('auth:sanctum')->group(function () {
    Route::post('/logout', [AuthController::class, 'logout']);
    Route::get('/me', [AuthController::class, 'me']);
});
```

### 完了条件

- `POST /api/login` が未ログインでも呼べる。
- `POST /api/logout` と `GET /api/me` はログイン必須になっている。
- 失敗時は JSON のエラーが返る。

## 7. Step 4: Model / Migration / Factory / Seeder を作る

### 目的

顧客、案件、タスクを DB に保存できるようにします。Laravel では、DB テーブルを Migration、テーブルに対応する PHP クラスを Model、テストデータ作成を Factory、初期データ投入を Seeder で扱います。

### 作業

Model、Migration、Factory をまとめて作ります。

```bash
docker compose run --rm --no-deps backend php artisan make:model Customer -mf
docker compose run --rm --no-deps backend php artisan make:model Project -mf
docker compose run --rm --no-deps backend php artisan make:model Task -mf
```

`users` テーブルには `role` を追加します。`admin` は削除可能、`staff` は登録・編集中心です。

主なテーブルは次の構成にします。詳細は [DBとModel設計](../03_詳細設計書/04_DBとModel設計.md) を参照してください。

| テーブル | 主なカラム |
| --- | --- |
| `users` | `name`、`email`、`password`、`role` |
| `customers` | `name`、`contact_name`、`email`、`phone`、`address`、`status`、`memo` |
| `projects` | `customer_id`、`owner_id`、`title`、`amount`、`status`、`start_date`、`due_date`、`description` |
| `tasks` | `project_id`、`assignee_id`、`title`、`due_date`、`status`、`memo` |

Model には、保存を許可するカラムとリレーションを定義します。

```php
class Customer extends Model
{
    /** @var array<int, string> 画面から登録・更新できる項目です。 */
    protected $fillable = [
        'name',
        'contact_name',
        'email',
        'phone',
        'address',
        'status',
        'memo',
    ];

    /**
     * この顧客に紐づく案件一覧です。
     */
    public function projects(): HasMany
    {
        return $this->hasMany(Project::class);
    }
}
```

Seeder では、ログイン用ユーザーとサンプルデータを作ります。初期データの内容は [初期データ設計](../03_詳細設計書/06_初期データ設計.md) を参照してください。

### 完了条件

- `php artisan migrate` でテーブルを作成できる。
- `php artisan db:seed` で `admin@example.com` と `staff@example.com` を作成できる。
- Model のリレーションで、顧客から案件、案件からタスクをたどれる。

## 8. Step 5: CRUD API と権限チェックを作る

### 目的

顧客、案件、タスクを API から一覧表示、登録、詳細表示、更新、削除できるようにします。

### 作業

API Controller を作ります。

```bash
docker compose run --rm --no-deps backend php artisan make:controller Api/CustomerController --api --model=Customer
docker compose run --rm --no-deps backend php artisan make:controller Api/ProjectController --api --model=Project
docker compose run --rm --no-deps backend php artisan make:controller Api/TaskController --api --model=Task
```

`backend/routes/api.php` に `apiResource` を追加します。

```php
use App\Http\Controllers\Api\CustomerController;
use App\Http\Controllers\Api\ProjectController;
use App\Http\Controllers\Api\TaskController;

Route::middleware('auth:sanctum')->group(function () {
    Route::apiResource('customers', CustomerController::class);
    Route::apiResource('projects', ProjectController::class);
    Route::apiResource('tasks', TaskController::class);
});
```

Controller では、次の形にそろえます。

| 処理 | レスポンス |
| --- | --- |
| 一覧 | `{ "data": [ ... ] }` |
| 詳細、登録、更新 | `{ "data": { ... } }` |
| 削除 | `{ "message": "..." }` |
| 入力エラー | `422 Unprocessable Entity` |
| 未ログイン | `401 Unauthorized` |
| 権限不足 | `403 Forbidden` |

削除は `admin` だけ許可します。

```php
/**
 * 顧客を削除します。
 *
 * 削除は影響が大きいため、admin 権限のユーザーだけ許可します。
 */
public function destroy(Request $request, Customer $customer): JsonResponse
{
    abort_unless($request->user()?->role === 'admin', 403, '管理者のみ削除できます。');

    $customer->delete();

    return response()->json(['message' => '顧客を削除しました。']);
}
```

### 完了条件

- `staff` は登録・編集できるが削除できない。
- `admin` は削除できる。
- React が期待する JSON 形式で返している。
- 入力チェックに失敗したとき、画面に表示できるエラーが返る。

## 9. Step 6: Dashboard API を作る

### 目的

ダッシュボード画面に表示する集計値を返します。

### 作業

Controller を作成します。

```bash
docker compose run --rm --no-deps backend php artisan make:controller Api/DashboardController
```

`GET /api/dashboard/summary` を追加します。

```php
use App\Http\Controllers\Api\DashboardController;

Route::middleware('auth:sanctum')->group(function () {
    Route::get('/dashboard/summary', [DashboardController::class, 'summary']);
});
```

返す内容は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| `counts.customers` | 顧客数 |
| `counts.projects` | 案件数 |
| `counts.open_tasks` | `done` 以外のタスク数 |
| `project_statuses` | 案件ステータスごとの件数 |
| `upcoming_tasks` | 期限切れを含む、期限が7日以内で未完了のタスク最大5件 |

### 完了条件

- `GET /api/dashboard/summary` がログイン必須になっている。
- 件数と期限間近タスクが JSON で返る。
- React のダッシュボード画面に数値が表示される。

## 10. Step 7: Feature Test と React 連携を確認する

### 目的

作った API が仕様どおり動くことを、自動テストと画面操作で確認します。

### 作業

Feature Test を作ります。

```bash
docker compose run --rm --no-deps backend php artisan make:test AuthApiTest
docker compose run --rm --no-deps backend php artisan make:test BusinessApiTest
```

最低限、次のテストを作ります。

| テスト | 確認内容 |
| --- | --- |
| ログイン成功 | 正しい認証情報でユーザー情報が返る |
| ログイン失敗 | パスワード誤りで `422` になる |
| 未ログイン制御 | 業務 API が `401` になる |
| 業務データ作成 | 顧客、案件、タスクを順番に作成できる |
| staff 削除不可 | `staff` は削除 API で `403` になる |
| admin 削除可 | `admin` は削除 API を実行できる |
| ダッシュボード | 件数が期待どおり返る |

テストを実行します。

```bash
docker compose run --rm backend php artisan test
```

React のビルドも確認します。

```bash
docker compose run --rm --no-deps frontend npm run build
```

最後に全体を起動します。

```bash
docker compose up --build
```

ブラウザで `http://localhost:5173` を開き、次を確認します。

```text
admin@example.com / password でログインできる
staff@example.com / password でログインできる
顧客、案件、タスクの一覧が表示される
登録、編集ができる
admin だけ削除ボタンが表示され、削除できる
ダッシュボードに件数と期限間近タスクが表示される
```

## 11. つまずいたときの見方

| 症状 | 確認すること |
| --- | --- |
| `docker compose up --build` が失敗する | `backend/artisan` があるか、`.env` の DB 設定が Docker Compose と合っているか |
| `SQLSTATE` エラーが出る | MySQL が起動しているか、`DB_HOST=mysql` になっているか |
| ログインで `419` になる | `/sanctum/csrf-cookie`、`SANCTUM_STATEFUL_DOMAINS`、CORS 設定を確認する |
| API が HTML エラーを返す | `bootstrap/app.php` で API エラーを JSON にする設定を確認する |
| `staff` で削除できてしまう | Controller の `destroy()` で `role === 'admin'` を確認しているか |
