# 業務管理システム 基本設計書 05_認証認可とエラー処理

## 1. 認証・認可設計

認証には Laravel Sanctum の Cookie 認証を使用します。

| 項目 | 設計 |
| --- | --- |
| 認証方式 | Cookieベースのセッション認証 |
| CSRF対策 | ログイン前に `/sanctum/csrf-cookie` を呼び、`X-XSRF-TOKEN` ヘッダーを付ける。 |
| セッション管理 | ログイン成功時にセッションIDを再生成する。 |
| 未ログイン制御 | `auth:sanctum` ミドルウェアで業務APIを保護する。 |
| 削除権限 | Controller の `destroy` で `role === 'admin'` を確認する。 |

画面側でも `admin` の場合のみ削除ボタンを表示します。ただし、画面表示だけでは安全ではないため、API側でも必ず権限チェックを行います。

## 2. エラー処理方針

| 状況 | APIレスポンス | 画面の扱い |
| --- | --- | --- |
| 入力エラー | `422 Unprocessable Entity` | 最初のバリデーションエラーを表示する。 |
| 未ログイン | `401 Unauthorized` | ログイン画面を表示する、またはエラーとして扱う。 |
| 権限不足 | `403 Forbidden` | APIから返されたメッセージを表示する。 |
| API通信失敗 | 状況に応じたエラー | 共通メッセージを表示する。 |

React 側では `ApiError` に HTTP ステータスとバリデーションエラーを保持し、`parseApiError` で画面表示用の短いメッセージへ変換します。
